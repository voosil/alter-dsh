# Agent 空间文档读写 · 评审摘要

> 完整方案见 [design-agent-space-documents.md](./design-agent-space-documents.md)（929 行，含完整工具契约、代码骨架与逐条证据）。
> 本文只保留「要你理解和拍板」的部分。

- 状态：设计待评审（未实现）
- 2026-11-09 评审更新：**写审批 = 直接执行（不询问）**；**首期不做浏览器实时刷新**；正文格式已收敛为 [spec-document-model-v0.md](./spec-document-model-v0.md) 的「JSON AST 权威 + Markdown 投影 + Document Operations」。
- **单仓库**：所有实现闭合在本仓库；`vendor/` 为项目自有源码目录（可改，变更在 `vendor/README.md` 登记）。
- 一句话：**在 `@alter-dsh/space` 的 Host 半侧注册 6 个 `space_*` 模型工具，进程内直连现有 `SpaceService`；难点不是"调通 API"，而是让 Agent 的写入可归属、可恢复，并且不与用户编辑互相踩踏。**（注：工具契约将按 spec §8 改为 outline/read/ops/generate 模型。）

---

## 1. 做什么

| 工具 | 作用 |
| --- | --- |
| `space_list` | 列空间；或列某空间的文档树（不含正文） |
| `space_search` | 按关键词搜文档，返回摘录 |
| `space_read` | 读文档（HTML 原文，默认 12k 字符、可续读；返回 `updated_at` 作为写基准） |
| `space_create` | 新建文档（归属 Alter） |
| `space_edit` | 精确字符串替换（首选）或整篇重写；**必须带 `base_updated_at`** |
| `space_comment` | 以 Alter 身份评论 |

首期只做文档；随想、任务、旅程、硬删除不做。

## 2. 为什么是 Host 原生工具

| 备选 | 为什么不选 |
| --- | --- |
| MCP / HTTP 中转 | 多一跳、要重新解决 Connection 鉴权，毫无收益 |
| 把文档导出成文件，复用 `read`/`edit` | 丢空间结构/评论/版本/归属，双向同步会打架 |
| PTC / code-mode | 本 profile 未启用 PTC，调试与审批更复杂，适合远期 |

核心优势：工具运行在 Host 进程内，可以**直接复用单写者队列、版本记录和事务**，这是所有安全设计的基础。

## 3. 三个真正的技术难点（本方案的主要设计价值）

| 难点 | 现状 | 解法 |
| --- | --- | --- |
| **归属** | vendor 把作者硬编码为 `'me'`（创建、版本、评论） | 在 store 外层加 `withWriteScope` 包装器：Agent 写入在同一事务里把新增节点/版本/评论打标为 `'alter'`，活动流自然显示「Alter 更新了」 |
| **并发** | 浏览器自动保存是 700ms 防抖**整篇覆盖**；Agent 与用户可能互相覆盖 | 写工具强制 `base_updated_at`，CAS 门禁放在**同一个 `store.update` 事务内**（不是先查后写）；冲突不落盘，返回当前值让模型重读 |
| **可恢复** | vendor 版本记录有 **5 分钟节流**，被覆盖的内容可能无历史可恢复 | Agent 写入时若本次没产生版本，宿主在同一事务补记一条 `'alter'` 版本（默认开，受既有 10 版/64KiB 裁剪约束） |

## 4. 其余安全决策

- **HTML 清洗**：正文会被产品 UI 以 `innerHTML` 渲染，Agent 输入的 HTML 必须过白名单清洗（去 `script`/`on*`/`javascript:` 等）；整篇重写全量清洗，精确替换只过滤新增片段。
- **写审批 = 直接执行（已确认）**：不弹审批，Agent 写入后立即生效。底气是三层可恢复性：强制版本（每次写入可回滚）、版本历史（10 版/篇可调）、每日整库快照。配置项保留 `never / always / destructive` 三档，默认 `never`。
- **恢复深度提醒**：每篇文档的版本历史有「10 版 / 64 KiB」上限（设置页可调），大文档可能只留得下最近几版；更久远的恢复靠每日快照。若希望"随便乱搞都能恢复"，建议把「版本历史上限」调到 20–30（设置 → 存储与备份）。
- **大小上限**：单篇正文 ≤256 KiB；读默认 12k、最大 40k 字符/次。
- **不伪造活动**：读工具不调用 `recordOpen`（否则会改变用户的活动度/未读）。
- **权限**：`AgentPermission` 目前只是产品元数据、无执行点；首期用插件配置门禁 + 只暴露安全操作，协作者权限映射留到后续。

## 5. 浏览器同步：首期不做（已确认）

产品目前不是协作产品，不需要"Agent 写完面板立刻变"。首期策略：

- **何时能看到 Agent 写入**：重新进入文档、切换空间、切走面板再回来、或刷新页面时，`SpaceApp` 会重新拉取数据；不需要改客户端代码。
- **仍保留 Agent 侧 CAS**（§3）：Agent 不会覆盖用户在两秒前刚保存的内容——过期 `base_updated_at` 会直接失败并让模型重读。
- **用户旧草稿覆盖 Agent 写入**：不做拦截，靠强制版本 + 每日快照可恢复（评审已接受这个取舍）。
- **后续可选**：浏览器保存 CAS + 冲突横幅、`watchRevision` 轮询 + 软刷新。设计已保留在完整文档 §9，等产品需要"协作感"时再启用，不占首期工期。

## 6. 工作量

| 阶段 | 内容 | 预估 |
| --- | --- | --- |
| P0 | 只读工具（list/search/read）+ 截断/投影 + 测试 | 1–1.5 人日 |
| P1 | 写包装器（归属/CAS/强制版本）+ create/edit/comment + 测试 | 2–2.5 人日 |
| P2（后续可选） | 浏览器保存 CAS + 冲突 UI；revision 轮询 + 软刷新 | 1.5–2 人日 |
| P3（后续可选） | 移动/归档/历史/评论管理、协作者权限映射 | 1.5–2.5 人日 |

**首期只需 P0 + P1，约 3–4 人日。** 工具 schema 首 token 成本约 +1.0–1.5k tokens（≈+12–15%）。

## 7. 需要你拍板的事项

### 7.1 写审批（已确认：直接执行）

- 默认 `never`：创建/修改/评论都不询问，立即执行。
- 可恢复性：每次写入都有 `'alter'` 版本 + 每日快照；误写可用历史/快照回滚。
- 代价：Agent 犯错没有事前拦截，只能事后恢复；大文档历史深度受 64 KiB/篇限制（见 §4）。

### 7.2 浏览器实时刷新（已确认：首期不做）

见 §5。后续需要时再加，不影响首期架构。

### 7.3 正文格式（待确认，先解释清楚）

**问题是什么**：空间文档在数据库里存的是 **HTML**（富文本编辑器产出的片段），比如：

```html
<p>周会结论：<strong>先做 P0</strong></p>
<ul><li>只读工具优先</li><li>写入带版本</li></ul>
```

「正文格式」这个决策问的是：**Agent 读写时以什么格式看到/提交正文**。

| | A. 直接用 HTML（建议） | B. 转成 Markdown |
| --- | --- | --- |
| 读 | 原样返回 `<p>…</p>` | `HTML→Markdown` 转换后返回 |
| 写 | 精确替换 HTML 片段 | `Markdown→HTML` 转换后写入 |
| 好处 | 零转换损失，加粗/列表/表格/图片/颜色原样保留；编辑是精确替换，不会重排用户没让改的内容；不引第三方库 | 模型更熟悉 Markdown，token 更省，写起来更自然 |
| 代价 | 标签占 token；长文里模型要小心复制标签 | 转换有损：颜色/高亮/对齐/嵌套结构/自定义属性会丢或变形；写回常会整篇重排，用户原格式可能被改；需引转换库；读取与编辑的基准格式必须统一，否则精确匹配更易失败 |

**实际影响**：主要影响模型编辑的准确率与 token 成本，不影响功能可行性。

**进一步调研（重要）**：把你的未来预期（图片、高亮块、mindmap、AI 可交互组件）放进来后，结论要更新——见 [research-document-storage-format.md](./research-document-storage-format.md)。2026-11-09 讨论后已收敛为**混合架构**（调研文档 §11）：

- **权威存储：JSON AST**（block/inline 节点树 + 稳定 block id，Tiptap/ProseMirror 编辑）；
- **AI 读：Markdown 投影**（带块索引/锚点，只读、可裁剪）；
- **AI 写：Document Operations**（insert/update/move/transform 等，带 baseRevision、校验、审计、可撤销）；**内容生成**（新章节/新块）允许直接输出 Markdown 再解析为新节点；
- **对象与资产旁表**：mindmap/交互组件/图片走引用，不内联进正文；application 组件有独立 schema 与沙箱运行时；
- 两个必须守住的边界：**Markdown 是投影不是第二真源**；**不要把整篇 Markdown 解析回 AST 做修改**（结构修改只走 Operations）。

无论最终细节怎么定，**之前按 HTML 精确替换实现的 Agent 工具设计作废**，Agent 工具将改为 `space_outline / space_read / space_ops / space_generate / space_object_*`。

## 8. 主要风险（Top 5）

| 风险 | 缓解 |
| --- | --- |
| 用户旧草稿覆盖 Agent 写入 | 强制版本 + 每日快照可恢复（首期不做浏览器拦截，已接受） |
| Agent 覆盖用户刚保存的内容 | Agent 侧 CAS：过期 base 直接拒绝；不自动 merge |
| HTML 注入导致面板渲染异常 | 白名单清洗 + 大小上限 |
| 工具对所有 Agent 可见（含子 Agent） | 配置门禁；后续按 preset 或插件作用域收窄 |
| `vendor` 同步后行为漂移 | 依赖的字段/行号已列入完整文档附录 B，升级后跑 agent-tools 测试 |

## 9. 建议的下一步

1. 正文格式方向已收敛：JSON AST 权威 + Markdown 投影 + Document Operations（见调研文档 §11）；
2. **v0 规范已写**：[spec-document-model-v0.md](./spec-document-model-v0.md)（节点模型/Schema Registry/投影/op 集/对象资产/工具契约/存储映射/验收标准）；下一步按 §9–§10 做 **3–5 人日最小垂直切片**，用 10 篇真实文档 + 6 类 Agent 任务验证成功率/轮次/token；通过后再排完整编辑器、组件运行时与迁移，最后回到 Agent 工具（P0/P1）实现；
3. 若暂不换编辑器，则只能先从 P0（HTML 只读工具）过渡，但写入工具不建议在 HTML 上投入。
