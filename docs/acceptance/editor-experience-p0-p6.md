# 编辑器体验重建 · P0–P6 验收清单

重建目标：**存储只有 `alter-doc/1` AST；人编辑文档体验与旧 HTML 编辑器一致；AI 能读 Markdown 投影并做块级 patch 编辑。**
旧体验基线取旧编辑器删除前的 `c73c3f6`。实现按 P0→P6 分阶段推进；P5 与 P3/P4 因依赖关系并行回填，提交顺序以 git 历史为准。每阶段条目通过、`pnpm check` 全绿后提交；全部完成后派发独立子 Agent 复验。

## 0. 口径与不变量

- **存储**：所有 note 正文恒为 `alter-doc/1`；无 HTML 持久化、无旧格式分支、无旧格式数据。
- **写入**：正文只经 Document Operations；`space.saveNode` 只更新元数据。
- **AI**：读 Markdown 投影、写 Operations；patch 为块级精确编辑，禁止整篇覆盖；真人编辑保存后 block id 稳定。
- **验证方式**：`自动`＝单测/集成/jsdom；`人工`＝真实 GUI 浏览器操作并留证据；每阶段门禁＝`pnpm check` 全绿 + 本阶段条目通过 + commit。
- **证据**：命令与输出、测试文件名、GUI 操作记录/截图、必要时数据库校验（节点为合法 AST、无 `contentFormat`）。
- 数据安全与并发细节以 [即时编辑器健壮性清单](document-editor-robustness.md) 的 A–G 组为准，本清单不重复展开；本清单 P0–P6 不把 A–G 全量当作整体门禁，A–G 未完成项按该清单自身标记跟踪。

## 2. P0 保存生命周期

- [x] **P0-1 自动保存**：正文与标题修改后约 700–1000ms 静默保存成功，无成功提示打扰。
- [x] **P0-2 失败可见可重试**：保存失败显示「保存失败，重试」；点击重试不丢当前输入。
- [x] **P0-3 切换/卸载 flush**：切换文档、关闭页面、切后台前保存或落草稿；重开可恢复。
- [~] **P0-4 崩溃恢复**（jsdom 覆盖恢复/丢弃；真实强制退出待验）：强制退出后重开文档，检测到未保存草稿，可恢复或丢弃。
- [x] **P0-5 保存中继续输入**：保存回执不覆盖保存期间的新输入，保存完成后自动排下一批。
- [x] **P0-6 大变更可保存**：≥64 个顶层块的文档做全选替换/清空/大重排，一次保存成功，无「变更过大」死路。
- [x] **P0-7 冲突不丢输入**：`doc/conflict` 时本地内容保留为草稿并给出可操作下一步；若服务端已落盘则和解为「已保存」。
- [x] **P0-8 幂等与重试**：网络失败重试不产生重复内容或重复 revision。
- [x] **P0-9 状态一致**：revision 单调；标题、正文、草稿状态一致；手动保存不再是主路径。
- [x] **P0-10 文本编辑不重建**：保存成功不重建编辑器实例，光标/选区/撤销历史保留。
- 自动化：autosave 调度与草稿/冲突和解单测；jsdom 输入→定时→保存、失败重试、回收草稿用例；Host 大批量 apply 集成测试。
- 人工：真实 GUI 输入等待后刷新内容在；断网后重试；切文档再回来恢复；大文档全选替换保存。

## 4. P2 评论与历史

- [x] P2-1 划词评论：选区锚定、正文高亮、评论轨折叠/展开，reload 后仍锚定。
- [x] P2-2 评论卡片：发布、编辑、补充、删除、解决；quote 随编辑更新。
- [~] P2-3 锚点失效：编辑/版本恢复后失效可感知（越界/块删除标记「锚点已失效」），尚未提供「重新锚定」交互。
- [x] P2-4 底部「子文档 / 全文评论」tab 与历史评论弹窗。
- [x] P2-5 历史：版本列表、AST 差异预览、恢复；大文档恢复走一次批量重放（上限 8192 个操作，覆盖单文档 5000 块上限）。
- 自动化：锚点映射/失效单测、版本恢复集成；人工：划词评论→刷新→点击定位；历史 diff/恢复。

## 7. P5 AI patch 体验
