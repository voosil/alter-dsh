# 空间对话方案（页面对话 · 侧边对话 · 引用）

产品需求：在空间里读页面时向 AI 提问、把主对话划选文本分支成侧边讨论、把空间/页面链接变成可理解的引用。数据契约见 [specs/space-chat-v0.md](../specs/space-chat-v0.md)；本文记录取舍与被否方案。

## 1. 复用 DSH 右侧栏，不新建面板

DSH 的右栏（`ui-sidebar-right`）是每个会话一个 docking surface，tab 类型开放注册（`sidebarRightTabs` 两段式：类型声明 + keyed body），对话/文件/终端都走同一条路。被否方案：

| 备选 | 为什么不选 |
| --- | --- |
| 空间插件自建一个右侧抽屉 | 与对话页右栏并存两套展开逻辑，抢同一块屏幕；导航（`sidebarRight.openTab`）、去重、宽度、fullscreen 全部重做 |
| 把页面塞进既有文件预览 tab | 页面是业务对象（编辑/评论/历史），不是工作区文件；复用 `SpaceApp` 才能保住体验 parity |
| fork 出的侧边对话用只读快照渲染 | 分支要继续对话；必须是有输入的活会话 |

空间页面 tab 直接渲染 `SpaceApp`（自带目录/搜索/多空间切换），每标签一个私有内存 router；`keepMounted` 保住滚动与草稿状态。「右侧栏开关」用 DSH 自己的头部角落按钮（对话页）+ 空间视图里的开关（桥接 `sidebarRight.toggleExpanded`），不新造面板。

## 2. 页面对话 = 空间映射工作区里的普通会话

页面菜单「AI 对话」/ 右栏「新建对话」创建的都是**普通 DSH 会话**，开在空间映射的工作区里（`space.getWorkspaceLink` 读绑定），这样 Agent 的工作目录与空间一致，数据则全部经空间工具读取。被否：无工作区的裸会话（Agent 丢目录上下文）；把引用写进会话记录（DSH 会话归 DSH 管，插件不可写）。

## 3. 侧边对话用 fork，继承语义白拿

`sessions.fork` 不带 `atSeq` 就是「最近已完成轮次前缀」——与规范的继承规则完全一致，正在生成的回复天然不进入。被否方案：手动复制历史（要处理流式窗口与工具卡片投影，复杂且易错）；subagent 子会话（入口在父会话的 subagent 目录，不是我们要的交互，且创建路径在 Host 侧）。

已知偏差：fork 出的会话出现在左侧列表。规范的「不出现」需要 DSH 的会话隐藏位；P0 接受并记录，待 DSH 收敛。

## 4. 引用：卡片是 UI，读取走既有工具

引用不新增任何 Agent 工具：卡片只是「上下文范围」的可见声明，Agent 读页面/空间内容用既有 `space_browse` / `space_doc_*`。被否：新增 `space_chat_context` 工具（多一个工具面、与既有读取重复）；把引用正文在发送时内联进 prompt（长页面失控、无按需读取）。

P0 的 composer 内引用是链接文本而非 chip：DSH composer 的引用 chip 只能由其触发管线插入，插件侧没有公开的 chip 插入 API。发送后的卡片渲染（userText 规则）不受影响，交互损失仅限发送前的视觉形态。

## 5. 历史视图 tab 用「条件注册」实现显隐

`conversation.view` 是静态注册，但 inject effect 可订阅数量并在 0↔1 时注销/重注册，View tab 行随之刷新——精确实现「数量为 0 时 tab 不出现」。被否：常驻注册 + 空态（违反规范）；把历史塞进 DSH 的 More 菜单（入口层级不对）。

## 6. 反向索引在 Host，一查即得

「相关会话」按 `chat_refs(space_id, node_id)` 表查询 + 会话排序，引用 state 派生与列表读取共用一套解析。被否：客户端全量拉取后过滤（数据量大时无谓传输）；把引用写进 DSH 会话元数据（插件无写权）。

## 7. 「已完成未读」用 DSH 置位、插件确认

DSH 的 `uiSession.sessionStatus` 已有 `completionUnread`：生成结束时如果主视图没有持有该会话就置位，且**只会被主视图清除**。侧边对话始终在右栏标签里，所以直接把 DSH 的标记画成「已完成」会永远不消失。方案是保留 DSH 作为「什么时候完成的」唯一来源，把「用户看过没有」交给插件：

- 分支标签页**可见**（`useTabInfo().tab.visible`）时自动确认，右栏收起或切走标签则保留标记；
- 历史行「打开」在开标签前确认；
- 再次生成结束后重新标记（DSH 先清后置，插件不缓存已完成状态）。

被否方案：完全自建「运行中 → 空闲」的本地未读状态（和 DSH 的置位重复，且刷新后不知道期间是否完成过）；把右栏标签当作主视图保留（`retain` 的 `mainView` 计数由 DSH 会话面板独占，插件没有这条通路）。
