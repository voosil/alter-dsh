# 正文排版：规则与依据

这篇方案说明文档正文内容区按什么规则排版、正文栏宽度如何取，以及这些规则凭什么定。它只覆盖正文内容区
与正文栏宽度；壳层、工具栏、slash 菜单、评论轨与历史面板的视觉仍按[编辑器还原验收](../acceptance/editor-experience-p0-p6.md)冻结。

## 冻结范围的收缩

- **决策**（2026-11-12 产品授权）：正文内容区的排版与正文栏宽度解冻，由本篇管理；编辑面其余部分继续冻结。
- 边界：`Editor.module.css` 里 `.surface` 之下的内容规则（排版与块级外观）可改；正文栏宽度的增量仅限
  `.paper` 的宽度/定位与手柄样式（见[正文栏宽度拖动](#正文栏宽度拖动)）；`.floating`、`.toolButton`、
  `.slashMenu`、`.linkBar`、`.wordCount` 等浮层与工具栏规则仍冻结。
- 内核的结构归一化（`kernel.css`）只中和 ProseMirror 多出来的一层包装，不引入视觉语言；
  它引用的间距一律走 `.surface` 上定义的节奏变量，不写第二套数值。
- 语法高亮的 token 类名由内核装饰器生成，颜色写成 `.surface` 里的 `:global(.alter-code-*)`
  规则并全部来自令牌——正文视觉仍只有这一份样式表。

## 为什么不能整包引入

社区里被当作「通用编辑器样式」传播的东西分四层，可移植性差别极大：

| 层 | 解决什么 | 代表 | 能否整包替换 |
| --- | --- | --- | --- |
| ① 阅读排版 | 标题阶梯、段距、行宽、行高 | Tailwind Typography、github-markdown-css | 能，但只覆盖文字 |
| ② 块级视觉 | 引用、代码、表格、任务、块选中 | BlockNote、Milkdown、ProseMirror | 不能：与自身组件、DOM 契约绑定 |
| ③ 中文处理 | 中西文混排、标点挤压、每行字数 | heti（赫蹏） | 能，纯 CSS + 可选脚本 |
| ④ 主题与令牌 | 颜色、圆角、语法高亮如何参数化 | Tailwind prose 变量、Radix、open-props | 只能借做法 |

真正「自带完整正文视觉语言」的只有 BlockNote、Milkdown Crepe、Lexical playground 三家；
Tiptap 官方、ProseMirror 基线、Editor.js 核心在正文排版上是空的，所以本篇的取值只能逐项对表，
不能换主题包。取数来源：各仓库源码与 npm/GitHub API（2026-11-12 与 2026-11-15 两轮），
中文部分取 W3C [clreq](https://www.w3.org/TR/clreq/)。

## 排版的角色与阶梯

正文 16px / 行高 1.9 不变（clreq 行距 50%–100%，1.9 落在区间内）。标题阶梯以正文字号为基准、
用 `em` 表达，改字号时整条阶梯自动跟随：

| 角色 | 字号 | 与正文比 | 主流取值 | 用途 |
| --- | --- | --- | --- | --- |
| 文档标题（输入框） | 32px | 2× | — | 壳层，不在本篇范围 |
| h1 | 26px | 1.625× | 32px（GitHub 2em、prose 2.25em） | 章节 |
| h2 | 22px | 1.375× | 24px（GitHub 1.5em） | 小节 |
| h3 | 18px | 1.125× | 20px（GitHub 1.25em） | 条目 |
| h4 | 16px | 1× | 16px | 靠字重区分 |
| h5 | 14px | 0.875× | 14px（GitHub .875em） | 靠字重 |
| h6 | 13px | 0.8125× | 12.8–13.6px（BlockNote .8em、GitHub .85em） | 字号 + 降一档色调 |
| 正文 | 16px | 1× | — | — |

- 相邻层级至少差 1.125×，与主流 1.2–1.25 的步长同向。
- **h1 封顶 26px**：本产品的文档标题已经占掉 32px 这一档，h1 再往上是与标题撞量级，不是阶梯问题。
  Notion（标题 40 / h1 30）与 Craft 用同一个办法留出标题的独特性。
- **h6 降到 13px**：旧值与 h5 同为 14px、只靠色调区分，六级标题在字号上不存在；现在字号与色调都差一档。
- 标题统一 600 字重、行高 1.3、零字距；上间距恒大于下间距。
- 被否：h1 提到 28–36px（2026-11-12 已否，本轮维持——28px 与 32px 的文档标题只差 4px）。
- Markdown 粘贴与 Agent 写入会带来 h4–h6（slash 菜单与文本类型菜单只给 h1–h3），因此也必须显式定规则，
  否则会落到浏览器默认的 1em 粗体配 21px 外边距。

## 垂直节奏

内容区只有两级间距，定义在 `.surface` 上（不进全局 token 表，避免壳层跟着变）：

| 令牌 | 值 | 用在 |
| --- | --- | --- |
| `--doc-gap` | 16px | 纯文本块：段落、列表、分隔线、任务列表 |
| `--doc-gap-block` | 20px | 自带表面的块：代码块、表格、图片、引用、链接卡 |
| `--doc-indent` | 1.75em（28px） | 列表缩进 |

- 段间距 16px = 1em：GitHub `p` 取 16px、UA 默认 1em、prose 取 20px；相对 30.4px 的行盒是 0.53 倍
  （主流 0.67 倍，prose 20/28、GitHub 16/24）。旧值 10px 只有行盒的 0.33 倍，段落断点很弱。
- clreq 建议段间距取行距的整数倍；1.9 行高下整行是 30.4px，取半行 16px 是「不在中文文档里叠出一整行空白」
  与「段落要能读开」之间的折中。被否：段间距直接拉到 24–32px。
- 块间距 20px 比段间距大一级，让代码块/表格/引用从文字流里浮出来；旧实现里代码块 24px、表格 24px、
  图片只有 14px、卡片 28px，同为媒体块却有四套数值，现在收敛成一处。
- **外边距语义是折叠而不是相加**：只给下方 `margin`，块之间取 `max()`。所以「前一段落 16px + 代码块 20px」
  得到 20px 而不是 36px。
- 文档首块上间距一律归零（`.surface > :first-child`，含列表首项），否则以代码块/引用开头的文档会凭空多出 20px。
- 标题间距同样是折叠语义，所以标题上间距必须大于 16px 才起作用。

## 标题间距

阶梯用 `em` 表达，绝对值随字号走，上间距在各层级递增、下间距恒小于上间距：

| 层级 | 上 | 下 | 绝对值（上/下） | 上:下 |
| --- | --- | --- | --- | --- |
| h1 | 1.35em | 0.45em | 35 / 12px | 3.0 |
| h2 | 1.35em | 0.5em | 30 / 11px | 2.7 |
| h3 | 1.4em | 0.5em | 25 / 9px | 2.8 |
| h4 | 1.4em | 0.5em | 22 / 8px | 2.8 |
| h5 | 1.5em | 0.5em | 21 / 7px | 3.0 |
| h6 | 1.5em | 0.5em | 20 / 6.5px | 3.0 |

- 上:下 主流是 2.0（GitHub 24:16、prose h2 48:24），我们取 2.7–3.0：行高 1.9 让段落的行内留白本来就大，
  下间距再大就不能把标题和它统辖的段落绑在一起。
- 标题上间距（20–35px）恒大于段间距 16px，所以「共用一个节奏」不会让标题读成一段普通文字。

## 行宽

正文栏宽度由令牌 `--alter-doc-width` 决定（`.paper` 的 `max-width`），2026-11-13 从 700px 放宽到 **760px**。

- 反馈：正文栏偏窄，长段落读起来局促。
- 取值依据：16px 正文下 760px ≈ 47.5 字/行，仍在 clreq 的 48 字上限之内；再宽（如 820px ≈ 51 字）
  就会越过上限，需要靠更大的行距或字号补偿，属于下一轮排版变更。
- 只动令牌，不动壳层：评论轨、正文栏与轨的间距、`@container` 收缩断点都不变；容器窄于 800px 时
  正文栏仍是撑满的（`max-width: none`），放宽令牌不改变窄屏观感。
- 被否：让正文栏跟随视口无级变宽。行宽随窗口跳动会让折行在调整窗口时不断重排，也给不同屏幕上
  「同一篇文档长什么样」增加变量；定宽令牌仍是默认口径，见下节的显式拖动。
- **可拖动是显式选择，不是新默认**：正文栏右缘的手柄允许把宽度调到 560–1120px；未拖动过时宽度
  仍来自令牌，拖动只写浏览器 localStorage，不进 Host，也不影响导出、版本与 Agent 读写。

### 正文栏宽度拖动

- **拖动**：手柄沿正文栏右缘，指针位移 1px 对应宽度变化 2px（栏居中，两侧对称变化）。
- **上限随可用宽度收敛**：实际宽度不超过所在轨道宽度减去两侧各 12px；评论轨打开或面板变窄时可用
  宽度变小，超出的宽度随之收窄。收窄期间向「更宽」方向的拖动/键盘操作是空操作，不改写已存的更大
  偏好；可用宽度恢复后宽度回到偏好值。这 12px 让步是手柄随附的最小 CSS 面，不扩散到其他壳层。
- **本地记忆**：宽度偏好只写浏览器 localStorage（`alter.space.docWidth`，只存 UI 偏好、不进 Host），
  刷新或重开面板后保持；不跨设备、不随文档同步。
- **复位**：双击手柄清掉本地偏好，恢复默认宽度。
- **键盘与可访问性**：手柄是 `role="separator"`、可聚焦，带当前宽度与上下限的 aria 值；方向键 ±16px、
  Shift + 方向键 ±48px、Home/End 跳到最小/最大。
- **窄布局与嵌入**：视口 ≤1100px 或正文容器 ≤800px 时正文栏本来就全宽，不显示手柄（可用宽度不足以
  调节时同样不显示）；嵌入 Workbench 预览沿用宽度偏好，也不显示手柄。

把宽度纳入本方案，是为了让「行宽」只有一处规则来源；它仍是正文排版决定，不等于放开壳层冻结。

## 列表

| 维度 | 取值 | 依据 |
| --- | --- | --- |
| 容器外边距 | 下 16px（= 段间距） | GitHub/prose/BlockNote 三个实现都是「容器间距 = 段间距」 |
| 容器上外边距 | 0，靠前一块的下间距折叠 | 折叠语义下与「也写 20px」等价，少一处数值 |
| 缩进 | 1.75em = 28px | 主流 24–40px、中位 28px；旧 1.6em（25.6px）时两位数序号会贴到文字 |
| 列表项间距 | 8px | 主流 4–8px；行距 30.4px 下 8px = 0.26 倍行盒（prose 0.29），「同一项折行」与「两项之间」可区分 |
| 嵌套列表 | 上 4px、下 0 | 旧实现把容器的 10px 下间距带进父项内部，父项末尾多出空白 |
| 序号字形 | `tabular-nums` | 9 → 10 时两位数序号不挤动列表左缘 |
| 标记颜色 | `--alter-text-muted` | 与正文分色，符号不抢字 |

「整个列表与其他行」的间距因此与段落完全同层：上 16px、下 16px，没有旧实现「上 4px 粘住、下 10px 分开」的偏斜。

## 行内代码

| 维度 | 取值 | 旧值的问题 |
| --- | --- | --- |
| 字号 | 0.875em（相对所处文字） | 写死 14px：22/26px 的标题里行内代码偏小一大截 |
| 内距 | 0.15em 0.35em（16px 正文下 ≈ 2px / 5px） | 写死 1px 4px，不随字号缩放 |
| 圆角 | `--alter-radius-xs`（6px） | 与 GitHub 同值 |
| 背景 | `--alter-code-surface` | 只给底色、不加边框（GitHub 同做法） |

附带效果：二级标题里写一段行内代码时，代码不再是固定 14px、比标题小两三档，而是跟着标题缩。

## 代码块与语法高亮

块级外观：外边距 20px、内距 12px 16px、圆角 `--alter-radius-control`、字号 0.875em、行高 1.6、
`tab-size: 4`（浏览器默认 8 列会把缩进推出可视区）、`white-space: pre-wrap` + `overflow-x: auto`、
`overscroll-behavior-x: contain`（横滚到边界不带动页面）。主流取值：字号 13–14px（prose .875em、GitHub 85%）、
内距 12–16px、行高 1.45–1.71。

**高亮是装饰，不是内容**：

- 内核用 ProseMirror 装饰器插件给 codeBlock 的文本打 token span（`src/document/editors/tiptap/code-highlight.ts`），
  文档 AST、节点、属性、撤销栈都不变，打开文档不会因为高亮改写它。
- 词法用 `lowlight` + `highlight.js`，只静态引入 18 个 grammar：javascript、typescript、json、css、xml、
  bash、shell、python、sql、yaml、markdown、go、rust、diff、java、c、cpp、ini。不引 `common` 全量（37 个）。
- 语言来源：先看 AST 的 `lang`（`ts`/`js`/`yml`/`sh`/`html`/`toml` 等 57 种拼写走别名表），
  `lang` 为空时才做保守探测（JSON 可解析、shebang、标记语言闭合标签、语言特征词、整块形态）。
  **声明了不支持的语言（`text`、`mermaid`、`scss`）保持纯文本**——作者已经说了它是什么，猜会把散文涂成代码。
  粘贴 GitHub 风格的 `class="language-x"` 时语言会落进 `lang`，不靠猜。
- 成本护栏：装饰器只在 doc 变化时重建，按「语言 + 正文」缓存 64 条，一次击键只重新词法化被改的那一块；
  IME 组合期间只做位置映射不重算（组合中替换文本节点会吞候选字）；超过 20000 字符的块不词法化。
- bundle 成本（实测）：`client.js` 1,558,799 → 1,649,565 字节（+88.6KB 未压缩），gzip 427,017 → 457,190
  （+29.5KB）。语言按需 import 是它能接受的原因；`common` 全量或 shiki 会把这个数字乘 2–5。
- 色板：9 个 `--alter-code-*` 令牌（暖调、低饱和），在 `--alter-code-surface` 上的对比度注释 4.7:1、
  其余 ≥5.3:1；diff 增删沿用 `--alter-diff-*`。**运算符与标点不上色**：括号、分隔符保持正文墨色，
  密集代码才不会变成调色盘（GitHub 浅色主题同做法）。暗色主题将来只换这一组令牌值。
- 不做语言角标：语言只存在于装饰器里，角标要么写进 AST（会改文档），要么用伪元素压在被编辑的文本上
  （抢光标命中区）。高亮本身就是「识别成什么」的反馈。
- 被否：`@tiptap/extension-code-block-lowlight`——它读 `attrs.language`，我们的 AST 用 `lang`，于是永远退化成
  `highlightAuto`（1000 行块 ≈ 70ms/次），且光标在任意代码块内移动都会重建全文高亮。
- 被否：`shiki`（同步引擎、13 语言 +149KB gzip）；自研分词器（10 语言 550–800 行且正确性更差）。

## 块级外观

| 块 | 决策 | 理由 |
| --- | --- | --- |
| 引用 | 外边距 20px，左内距 20px，1px 边框，文字 `--alter-text-secondary` | 靠色深拉层级而不是加粗彩条；主流 16–32px、内距 16–20px |
| 分隔线 | 外边距 16px，保留 7px 的点击内距 | GitHub 24px；7px 内距是块手柄的命中区，不能动 |
| 表格 | 外边距 20px；单元格内距 8px 12px；表头底色 `--alter-surface-hover` | 主流 GitHub 6px 13px、prose 8px；横向比纵向宽，数字列不挤 |
| 图片 | 外边距 20px | 旧值 14px 比代码块少 10px：同为媒体块却两种节奏 |
| 链接卡 | 外边距 20px | 旧值 28px 只能靠「卡片更大所以更松」解释 |
| 任务列表 | 行间距 8px（与列表项一致），容器下间距 16px | 勾选行与列表项读起来应是同一节奏 |
| 选区 | 透明度 0.12 | 原选区在浅色正文上几乎不可见 |

被否：引用改成 4px 圆头竖条（Milkdown 式）或浅底色块（heti 式）。前者要新增伪元素，与块悬停已有的
`::after` 高亮挤在同一元素上；后者需要一个本产品没有的引用底色令牌。

## 刻意不改的

- **行高 1.9**：偏离主流（1.5–1.8）但是有意识的选择，且落在 clreq 区间内。
- **不做 `text-wrap: balance/pretty`**：编辑态每次击键都会重排折行，标题与段落的视觉断点会跳动。
- **不做暗色主题、不做语言选择器**：色板已成令牌，暗色只是换一组值；语言选择器属于 AST 与工具栏契约的变更，
  不属于排版范围。
- **默认行宽 760px**（见上节）：拖动是用户显式选择，未拖动过时默认值与静息视觉不变。

## 风险

- 内容规则、正文栏宽度与浮层规则分布在相邻的样式表与规则块里；评审须确认 `.floating` 及其后的壳层
  规则未被触碰，正文栏增量只落在 `.paper` 与手柄。
- 宽度偏好是逐浏览器的本地量：换浏览器、换设备或清站点数据后回到默认 760px；它只是 UI 偏好，
  不进入文档、版本与导出。
- `:global(.alter-code-*)` 是本文件唯一读外部类名的出口。三处必须同步：内核 token 名
  （`CODE_TOKEN_TYPES`）、`.alter-code-*` 规则、`--alter-code-*` 令牌定义；`pnpm verify`
  逐项比对，任一处改名而另一处没跟上都会让门禁失败。
- 装饰器成本随文档里代码总量线性增长；缓存条数与 20000 字符上限是护栏，改护栏前先测输入延迟。
- 间距依赖外边距折叠：将来给块容器加 `padding`/`border` 会改变折叠结果，需要一并复查节奏。
- `em` 阶梯与间距依赖 `.surface` 的 16px 正文；容器级缩放（改根字号）不影响它们，两种做法不要混用。
