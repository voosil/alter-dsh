# 空间部署形态：本地权威与自部署服务端

## 问题

Space 作为开源的 DSH 插件交付，每个用户自己使用：默认本地安装即可用；希望多设备访问的用户可以把它部署到自己的服务器。现有实现只有本地权威一种形态，远端形态、接入方式、连续编辑与数据迁移都没有定义，容易把「服务器在线」与「本地化 + 同步」混成二选一。

## 结论

同一个插件、同一套协议支持两种权威形态，模式由配置选择，不拆成两个产品：

- **本地模式（默认）**：数据落在用户本机 DSH 的 `~/.dsh/data/space`；完整离线可用；保留「空间 ↔ 工作区」映射。
- **服务端模式**：用户在自有服务器部署独立的 Space 服务；本地 Host bridge 接入；服务端是唯一权威；多设备在线共享；本地保留读缓存与写队列，弱网与短时断网不中断编辑。

两种模式之间不做自动同步；切换通过显式迁移完成，同一时刻只有一个权威。

## 模式边界

| 维度 | 本地模式 | 服务端模式 |
| --- | --- | --- |
| 数据权威 | 本机 DSH Host 的 SQLite | 独立 Space 服务端的 SQLite |
| 离线与弱网 | 完整离线可用 | 缓存内容可读；编辑进入写队列，恢复后重放；未缓存内容需要在线 |
| 多设备 | 单设备 | 同一服务端的多设备在线共享 |
| 空间 ↔ DSH 工作区 | 保留现有映射 | 不映射（工作区是宿主/设备本地概念） |
| 空间目录 | 本机宿主选择器 | 服务端目录：远端浏览或手工输入，不使用本机选择器 |
| Agent 工具 | 本地直连业务服务 | 本地转发到服务端，工具契约不变 |
| 备份责任 | 用户本机快照 | 服务端快照 + 用户自行异地复制 |
| 鉴权 | 宿主自带 | 服务端命名 token |
| 迁移 | — | 双向；一致性快照 + 大库增量传输 |

## 关键决策

### 两种模式共用一个插件与协议

服务端模式只改变权威实现与传输，不改变客户端 UI、工具契约与写入语义。理由是开源交付只有一条安装路径、用户可以无感切换，实现也不必分叉。被否：拆成「本地版」与「服务器版」两个插件。

### 服务端是独立服务，以 Docker 交付

服务端只需 Node + SQLite 与业务代码即可运行，单容器 + 数据卷，配置经环境变量或挂载文件提供。理由是自部署成本低、无需把 Agent 与文件系统搬上云、升级与回滚可预期。被否：只提供源码运行或让整机 `dsh web` 充当正式形态。

### 服务端模式由本地 Host bridge 接入

浏览器与 DSH 桌面壳只能访问本地 Host；远端权威由本地 Host 的 bridge 代理 RPC 与资产请求。理由是客户端与桌面壳无需改动，鉴权 token 也只在 Host 侧。被否：客户端直连远端 API（跨源、凭据与素材路由都不成立）。

### Agent 工具在两种模式下契约一致

工具仍在本地 DSH 注册，服务端模式把调用转发到远端；模型看到的工具说明、参数与结果不变。被否：只允许服务端 Agent 访问空间。

### 服务端模式不建本地 DSH 工作区

空间目录属于服务器，映射到本机工作区没有稳定语义：路径、权限与「同一目录只归属一个空间」的约束都跨不上机器。被否：把远端路径映射成本地工作区。

### 鉴权使用单用户命名 token，不提供免鉴权模式

服务端配置支持多个命名 token，便于每设备一个、单独撤销与轮换；token 存 DSH credentials，界面只显示已配置。私网只降低网络暴露与传输风险，不替代应用鉴权。被否：账号与多租户；免 token 的私网模式。

### 配置入口与 Agent 可配置

设置页新增「服务器」区：模式、服务器 URL、token、连接状态与测试、切换与迁移入口。Space 的业务设置（服务器连接、存储策略、模式）统一走 Host 侧设置接口，Agent 通过模型工具读写同一接口，因此可以在对话里完成服务端部署与客户端配置。写入服务器目标或 token 属于敏感操作，必须经用户确认并记录审计。被否：只靠手改 profile 配置。

### 服务端模式的目录选择

空间目录使用远端目录浏览 + 手工输入，不使用本机原生选择器：原生选择器返回本机路径，与服务端语义不符。被否：把本机目录路径写入服务端空间。

### 服务端权威 + 本地缓存与写队列

连续编辑由本地 Host bridge 的读缓存与持久化写队列保证，服务端仍是唯一权威。目标是弱网/短时断网不丢内容、不阻塞输入；不引入本地权威的双向同步与 CRDT。被否：多主合并或 OT/CRDT 同步引擎。

## 本地缓存与写队列

- **读缓存**：资产按内容寻址，可长期缓存；文档、列表与目录按 revision 做 stale-while-revalidate，命中时先展示再后台刷新，并标记可能过期。
- **写队列**：bridge 持有待提交操作，按文档串行，携带幂等键与 `baseRevision`；先落盘再向界面确认，重连后按序重放。传输失败按退避重试；业务冲突不自动重试，保留为草稿或版本并提示用户处理。
- **状态呈现**：编辑面与设置页都展示「已保存到本地（待同步）」「同步中」「已同步」「冲突」；不得在未落盘时显示已保存。
- **草稿归属**：权威待提交批次由 Host 写队列持有；旧编辑面的浏览器崩溃草稿只作为恢复缓冲区，保存或冲突处理后清除，不承载业务权威。
- **存储与清理**：缓存与队列是本地附属数据，放在 DSH 数据目录的独立文件中，不写入权威库；按容量与保留期清理，损坏时丢弃缓存并从服务端重建。

## 数据迁移（双向）

本地模式使用一段时间、库里已有大量数据后再接入服务端是主要路径；服务端模式回退本地同样需要迁移。迁移以「一致性快照 + 增量传输」完成，不做在线同步，也不要求用户重新录入内容。

### 迁移边界

- **迁移**：`space.db` 与 `assets/` 资产字节；保持 id、revision、版本历史与资产引用不变。
- **不迁移**：`workspace_links`（设备本地的 DSH 工作区绑定）、浏览器 UI 偏好、本机路径语义（`directories` 原值保留，但在服务端模式按远端路径展示并提示重选）、本机 `backups/` 快照（目标侧自行重建快照轮换）。
- 切换是整库切换；切换后源侧库只读保留为回退点，不再写入。

### 大数据量流程（本地 → 服务端）

1. 预检：插件与服务端版本/schema 兼容、目标服务器为空库、容量与网络估算；源侧先做一次快照。
2. 资产预拷贝：资产内容寻址且不可变，可先增量、断点续传；预拷贝期间源侧仍可使用，并记录已传清单。
3. 冻结与快照：客户端进入迁移态（只读提示），落盘当前编辑，暂停源侧写入；用一致性快照导出 `space.db`。
4. 补齐与校验：传增量资产；校验 part sha256、schema 版本、`quick_check`、逐表行数与文件数；任何不一致中止迁移，源侧保持权威。资产字节由内容寻址与包内条目哈希覆盖。
5. 切换：服务端以新库启动并生成初始快照；客户端切到服务端模式并跑连接测试；源侧库与迁移快照保留为回退点。
6. 回退：服务端首次写入前可无成本切回本地；之后回退需要反向迁移（服务端快照覆盖本地）或放弃服务端新数据，界面必须明确损失。

### 服务端 → 本地

复用同一套快照与校验流程：服务端导出一致性快照与资产清单，本地 Host 下载、校验后替换本地库；同样先备份本地现状，失败不改变本地权威。跨模式切换必须经过迁移或显式放弃，不做静默覆盖。

替换库文件不是崩溃安全的：如果进程在「移走旧库 → 放入新库」之间退出，需人工用 `.migration/backup-*`
回退；启动只清扫超过 7 天的遗留暂存，不自动探测并恢复中断的替换。

### 工具形态与安全

设置页提供迁移向导（预检、进度、校验、切换、回退），同一套能力由 CLI 与 Agent 工具调用，Agent 只向用户索取服务器访问信息并执行机器可读步骤。传输优先走 HTTP 分块上传/下载（断点续传、校验和），大库也可用文件复制或 rsync；token 不进 URL 与日志；目标替换数据库前先备份。

### 大库的取舍

- 版本历史默认完整迁移；用户明确接受时可选择「仅当前版本」的缩小迁移（会丢历史，需二次确认）。
- 迁移耗时主要由资产体积决定；大库先完成资产预拷贝，再把数据库切换压缩到只读窗口内。
- 目标已有数据时必须先备份并要求显式覆盖确认，不静默合并。

## 服务端要求（产品约束）

- 独立启动：不需要 DSH 运行时；以 Docker 镜像交付，单容器 + 数据卷，配置经环境变量或挂载文件提供。
- 传输与安全：HTTP(S) + token；默认只监听本机或内网，公网部署要求 TLS 反向代理或私网（如 Tailscale）；不暴露未经鉴权的端口。
- 运维：健康检查、协议版本探测、每日快照、备份/恢复说明与升级回滚流程随服务端一起交付。
- 兼容：插件与服务端共享协议版本，不匹配时给出明确错误，不静默失败。

## 被否方案

- **云盘或 NAS 直接同步 `space.db`**：SQLite + WAL 不是同步安全格式，锁、半写与冲突副本会丢数据。
- **客户端直连远端 DSH `/api`**：桌面页面是自定义协议页面，跨源与 Host/Origin 鉴权不成立，素材路由也无法携带凭据。
- **整机 `dsh web` 上云作为正式形态**：能零代码验证多设备体验，但 Agent、终端与文件都在远端，且不是 desktop 面板。
- **本地权威双向同步 / CRDT**：单用户多设备不需要多主合并；引入同步引擎的复杂度远高于收益。

## 实现默认值

- token：服务端支持多个命名 token，客户端存其中一个；轮换与撤销通过更新服务端配置并重启生效。
- 敏感写入：Agent 修改服务器目标或 token 前请求审批，审计记录写入 Host 日志；设置页操作需要用户确认。
- 模式切换：运行时切换权威后端，不重启 DSH；切换必须经过迁移或显式放弃，不静默覆盖。
- 缓存位置：DSH 数据目录下的独立本地库；权威库与缓存库分离。
- 目录：远端模式使用服务端 `listDirectories` 浏览 + 手工输入。
- 迁移传输：HTTP 分块上传/下载为主，文件复制与 rsync 作为大库备选。
