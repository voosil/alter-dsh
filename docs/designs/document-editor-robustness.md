# 文档编辑器健壮性：还原后的现状与缺口

这篇方案回答「文档编辑器前端 1:1 还原后，健壮性现在处于什么状态、还缺什么、按什么边界推进」。
验收标准以[健壮性验收清单](../acceptance/document-editor-robustness.md)为准，本篇不复制条目；
内容架构与写入契约以[内容架构方案](document-content-architecture.md)和
[Operations 规范](../specs/document-operations-v0.md)为准。

## 1. 判断

- **前端冻结体验而非实现**：文档页与基线旧 UI 保持视觉与交互 parity（壳层与 CSS 不动）。
  唯一内核为 AST 原生 Tiptap（`src/document/editors/tiptap`），输入、撤销与渲染由它承担；
  kernel-agnostic 数据层在 `src/document/runtime`（保存生命周期、草稿、快照、Operations、评论锚点、
  冻结 HTML 投影/解析），经 `@alter-space/document-runtime` 接 Document Operations。
  内核替换与退役结论见[内核替换方案](editor-kernel-replacement.md)。
- **已落地并有自动化证据**：自动保存（约 700ms 防抖、成功静默、失败显示「保存失败，重试」）、
  标题经 `saveNode` 落库、版本恢复带 CAS、评论 quote→anchor 生成、data URL 图片/文件保存前物化为
  资产、外部 revision 变化时重载编辑面。
- **系统面已补齐并验证**：草稿与崩溃恢复（localStorage 草稿、恢复/丢弃/旧版本保留覆盖）、
  并发冲突 UX（≥4 条显式路径、双入口不静默覆盖、版本恢复脏状态确认）、输入层专项
  （IME 组合守卫、粘贴清洗与降级、空块/空列表项语义、撤销栈重置、无障碍标签）、异常兜底与
  诊断上报、客户端故障注入与真实浏览器回归均已落地；上限文档性能已测并锁定预算。
- **仍受限**：真实输入法、真实断网、5000 块上限文档的浏览器实测未覆盖；对象卡
  （callout/mindmap/component）在旧 UI 中仍为占位，无人工入口。
- **验收原则**：每条失败路径都有兜底与回归测试，而不是「零 bug」；未做项如实标 `[ ]`，
  不沿用改造前状态。

## 2. 目标与非目标

**目标**

- 输入不丢：未保存内容在切换、崩溃、并发与重试下都可恢复或明确告知。
- 失败可恢复：任何保存/加载失败都保留本地内容并给出下一步，不以「重新加载」作为唯一出口。
- 并发可收敛：人与 Agent 同时写入时保留双方修改，冲突有对比、合并或另存路径。
- 输入保真：IME、粘贴、拖放与媒体输入不静默丢内容，不安全内容不进入文档。
- 保存可行：变更规模不因单批操作上限或模型上限变成死路。
- 规模可预期：上限文档的加载、输入与保存在明确预算内；异常可观测、可回归。

**非目标**

- 不改造文档页的视觉与交互：壳层、CSS 保持基线 parity；健壮性增强落在 `src/document/runtime`
  数据层、外围壳层，或经产品明确批准的前端改动。
- 不做多人实时协同（CRDT/OT 服务端）与 presence；不做多端同步与移动端编辑。
- 不重写 AST/Operations 契约（新增 op 必须先升 spec）。
- 不做独立离线客户端；离线只覆盖「本地输入不丢、恢复后同步」。

## 3. 现状与缺口（按验收组）

| 组 | 现状 | 缺口 |
| --- | --- | --- |
| A 数据安全 | 自动保存/失败重试/草稿与崩溃恢复/冲突和解/保存期间输入/撤销栈重置均有自动化+浏览器证据 | 无（真实崩溃以页内 reload 等价验证） |
| B 并发与恢复 | 冲突 Dialog 多路径、双入口不静默覆盖、版本恢复脏状态确认与草稿保留 | 无自动合并（按决策不做） |
| C 变更可行性 | 64+ 块全选替换、4990 块/509.7KiB 往返与保存、超限可读错误 | 无 |
| D 输入层 | IME 组合守卫、粘贴白名单清洗、空块/空列表项语义、无障碍属性 | 真实输入法未实测 |
| E 正确性 | 错误边界/错误页、结构化诊断、评论锚点失效检测与自动重锚 | 遥测后端未接（console 入口） |
| F 规模性能 | F1 292ms / F2 p95 14.6ms / F3 776ms / F4 +0.58% heap，预算已锁定 | 真实低配机/冷启动面板加载待补测 |
| G 回归 | 内核映射往返、Host 随机操作序列、客户端故障注入、真实浏览器 9 类用例 | 真实断网与 5000 块浏览器实测未覆盖 |

A–G 的结论与实测数据来自已退役的 contentEditable 内核时代；当前内核的自动化证据在
`tests/ui/document/{page,runtime,editors/tiptap}/`，真实浏览器与真实输入法复核仍待进行。

## 4. 关键决策

- **数据层先行**：健壮性逻辑默认放在 `src/document/runtime` 与外围壳层；编辑面改动须产品明确批准。
  2026-11-11《编辑器专题优化》第 1–11 项与后续第 12–14 项获批后，编辑面只做行为级修复与最小 CSS 增量（选中态、表格操作条、
  附件态、placeholder 定位、整行输入 `---` 即时转分割线、slash 菜单方向随实例固定、引用标记 `>`/`》`+空格
  输入、引用行首退格只删标记），不重排 DOM/JSX，新增选中态不进 AST。
- **CAS 冲突不自动合并**：保存被拒时保留编辑面内容并提示重试；自动合并会隐藏语义差异。
- **资产不静默丢失**：data URL 物化失败时保留原内容并提示重试，不用占位替换用户内容。
- **大变更兜底优先分段**：按可独立提交的批次分段并显示进度；只有语义不可拆时才评估新增能力，
  且先升 spec。

## 5. 开放决策

- 对象卡（callout/mindmap/component）的人工入口：需要产品批准前端改动后才能恢复；当前仅 AI
  可读写、旧 UI 显示占位卡。
- 冲突是否要自动 rebase/块级合并：当前只提供显式路径（保留本地覆盖、重新加载、导出草稿）。
- 性能预算的基准机器与冷启动/多文档面板加载指标待补测。

## 6. 风险与依赖

- **冻结 HTML 投影保真**：历史差异预览与粘贴导入依赖 HTML↔AST 映射，未知标记必须可见降级并告警；
  保存链路不经过 HTML，内核直接捕获 AST。
- **DOM 冻结的约束**：错误提示、恢复入口与进度只能通过现有壳层或产品批准的新增 UI 呈现，
  设计空间受限。
- **写频率上升**：自动保存会放大写入与版本记录，需复核版本裁剪与备份策略。
- **旧草稿不再恢复**：旧 HTML 草稿格式（`alter-doc-legacy-draft/1`）已随旧内核退役删除，陈旧本地
  草稿不会恢复；保存与版本均为 AST，恢复底线不受影响。
- **回归基建**：已建立页面/运行时/内核单测与真实浏览器用例；headless 下合成
  键与鼠标选择受限，真实 IME/断网仍需人工或更强自动化补测。
- **体量约束**：新增第三方库必须打进客户端 bundle，选型前先评估产物大小。
