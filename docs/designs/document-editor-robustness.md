# 文档编辑器健壮性：还原后的现状与缺口

这篇方案回答「文档编辑器前端 1:1 还原后，健壮性现在处于什么状态、还缺什么、按什么边界推进」。
验收标准以[健壮性验收清单](../acceptance/document-editor-robustness.md)为准，本篇不复制条目；
内容架构与写入契约以[内容架构方案](document-content-architecture.md)和
[Operations 规范](../specs/document-operations-v0.md)为准。

## 1. 判断

- **前端按产品要求冻结**：文档页是重构前旧 UI 的 1:1 还原（DOM/CSS/既有 JSX 结构不改），
  编辑器内部输入、撤销与渲染由旧 contentEditable 实现承担；数据层经 `src/document/legacy` 适配
  `alter-doc/1` AST 与 Document Operations。
- **已落地并有自动化证据**：自动保存（约 700ms 防抖、成功静默、失败显示「保存失败，重试」）、
  标题经 `saveNode` 落库、版本恢复带 CAS、评论 quote→anchor 生成、data URL 图片/文件保存前物化为
  资产、外部 revision 变化时重载编辑面。
- **系统面仍欠**：草稿与崩溃恢复、并发冲突 UX（保留草稿、对比、重载、另存）、输入层专项
  （IME、粘贴降级、空块语义）、上限文档与性能预算、无障碍、客户端故障注入与浏览器级回归，
  均未在还原实现上完成。
- **验收原则**：每条失败路径都有兜底与回归测试，而不是「零 bug」；未做项如实标 `[ ]`，
  不沿用改造前状态。

## 2. 目标与非目标

**目标**

- 输入不丢：未保存内容在切换、崩溃、并发与重试下都可恢复或明确告知。
- 失败可恢复：任何保存/加载失败都保留本地内容并给出下一步，不以「重新加载」作为唯一出口。
- 并发可收敛：人与 Agent 同时写入时保留双方修改，冲突有对比、合并或另存路径。
- 输入保真：IME、粘贴、拖放与媒体输入不静默丢内容，不安全内容不进入文档。
- 保存可行：变更规模不因单批操作上限或模型上限变成死路。
- 规模可预期：上限文档的加载、输入与保存在明确预算内；异常可观测、可回归。

**非目标**

- 不改造文档页前端：CSS、编辑器 DOM 与既有 JSX 结构保持基线一致；健壮性增强只能落在数据层、
  外围壳层，或经产品明确批准的前端改动。
- 不做多人实时协同（CRDT/OT 服务端）与 presence；不做多端同步与移动端编辑。
- 不重写 AST/Operations 契约（新增 op 必须先升 spec）。
- 不做独立离线客户端；离线只覆盖「本地输入不丢、恢复后同步」。

## 3. 现状与缺口（按验收组）

| 组 | 现状 | 缺口 |
| --- | --- | --- |
| A 数据安全 | 自动保存、失败重试、版本恢复有自动证据 | 草稿与崩溃恢复、保存期间输入专项、恢复状态呈现 |
| B 并发与恢复 | 保存带 `baseRevision`，冲突时保留编辑面并提示重试 | 冲突对比/合并/另存、双入口保护、版本恢复脏状态保护 |
| C 变更可行性 | 块级 diff 受单批上限保护，超限报可读错误 | 上限文档（5000 块 / 512 KiB）验证、分段保存与进度 |
| D 输入层 | 旧编辑器自带输入与撤销行为 | IME 专项、粘贴降级、空块/空列表项语义、无障碍 |
| E 正确性 | 标题与正文分步落库，评论 anchor 生成 | 异常错误页、可诊断入口、锚点失效提示与重锚 |
| F 规模性能 | 未测 | 首屏/输入/保存/内存预算与基线 |
| G 回归 | 映射往返与 Host 随机操作序列有自动证据 | 浏览器级用例、客户端故障注入 |

阶段推进顺序建议：先补草稿与恢复状态（数据安全收益最大），再补冲突 UX，随后是输入层专项、
观测与规模回归；每一步以验收清单对应条目为准。

## 4. 关键决策

- **数据层先行**：所有健壮性逻辑放在 `src/document/legacy` 与外围壳层，前端 DOM/CSS 不动。
- **CAS 冲突不自动合并**：保存被拒时保留编辑面内容并提示重试；自动合并会隐藏语义差异。
- **资产不静默丢失**：data URL 物化失败时保留原内容并提示重试，不用占位替换用户内容。
- **大变更兜底优先分段**：按可独立提交的批次分段并显示进度；只有语义不可拆时才评估新增能力，
  且先升 spec。

## 5. 开放决策

- 草稿介质与恢复入口：在冻结 UI 外如何呈现恢复/丢弃，是否跨窗口共享。
- 冲突 UX 形态：保留草稿 + 重载、块级对比合并，还是先只提供「另存副本」。
- 大变更分段与进度呈现方式；是否需要在冻结 UI 外增加状态浮层。
- 性能预算数值与基准机器；验收清单中的暂定数值在规模阶段锁定。
- 验收清单何时从 `draft` 转 `active`：A–C 组通过后先转，后续组滚动验收。

## 6. 风险与依赖

- **适配层保真**：HTML↔AST 双向映射的质量决定保存是否丢内容；未知标记必须可见降级并告警。
- **DOM 冻结的约束**：错误提示、恢复入口与进度只能通过现有壳层或产品批准的新增 UI 呈现，
  设计空间受限。
- **写频率上升**：自动保存会放大写入与版本记录，需复核版本裁剪与备份策略。
- **回归基建**：浏览器级 IME、粘贴与故障注入需要先搭，否则「修好又回归」概率高。
- **体量约束**：新增第三方库必须打进客户端 bundle，选型前先评估产物大小。
