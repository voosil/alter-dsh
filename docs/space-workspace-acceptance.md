# 空间 ↔ DSH 工作区映射 · 验收清单

实现目标：新建空间时把**主工作目录**（`space.directories[0]`，其余为参考目录）映射为一个 DSH
原生工作区；工作区标题为 `🪐 <空间名>`；空间改名时同步；空间删除/归档只做单向的、非破坏性处理。

> 结论口径：DSH 工作区以 `fs.realpath` 后的目录为唯一身份，一个目录最多一个工作区、一个空间主目录
> 绑定一个工作区。绑定关系保存在插件自己的 SQLite 侧表（`workspace_links`），不写入 `vendor/` 的 Space 实体。
>
> 状态：`[x]` 自动化测试覆盖；`[~]` 实现已确认、依赖 DSH 既有运行时链路（本环境无法做浏览器联调）；
> `[ ]` 未做。

## A. 创建空间

- [x] **A1** 新建空间未选择任何工作目录 → 创建失败，提示「至少需要一个工作目录」，不产生空间。
- [x] **A2** 新建空间选择多个目录 → 只有第 1 个目录（主目录）创建工作区；其余目录不创建。
- [~] **A3** 创建成功后 DSH 侧栏出现工作区（Host 写入 `workspaceRegistry` 后由 `domain/changed` →
      workspace feed 推送），标题为 `🪐 <空间名>`，路径为主目录的 canonical 绝对路径；无需刷新页面。
- [x] **A4** 主目录支持 `~/...` 与绝对路径；`~` 展开为宿主 home；目录不存在 / 不是文件夹 / 非绝对路径 → 创建失败。
- [x] **A5** 主目录已有工作区但未被任何空间占用 → 复用同一 workspace id（不新建、不移动），
      标题改为 `🪐 <空间名>`，该工作区原有会话归属（`sessionIds`）保持不变。
- [x] **A6** 主目录已被其他空间（含已归档空间）占用 → 创建失败并提示占用者名称；不创建空间、不改动对方工作区。
- [x] **A7** 空间名重复 → 工作区标题去重为 `🪐 名称（2）`、`🪐 名称（3）`…，不覆盖已有标题。
- [x] **A8** 空间创建失败（名称非法等）→ 若本次已新建工作区且无会话，回滚删除该工作区；接管的工作区恢复原标题。
- [~] **A9** 创建后重启 DSH / 插件：工作区注册仍在，空间 ↔ 工作区绑定仍在（SQLite 持久化）。
      绑定侧表持久化已测；工作区注册的持久化由 DSH `workspaceRegistry`（domain storage）保证，未做真实重启联调。

## B. 空间改名

- [x] **B1** 空间改名 → 关联工作区标题同步为 `🪐 <新名>`；重名规则同 A7。
- [x] **B2** 用户在 DSH 里手工改工作区标题 → 空间侧不回写；下一次空间改名时覆盖为空间名（设计已接受）。
- [x] **B3** 工作区已被用户从 DSH 删除 → 空间改名不报错、不自动重建，空间数据不受影响。

## C. 主目录变更（空间配置）

- [x] **C1** 主目录改为新目录 → 旧工作区解绑、保留注册、去掉 `🪐 ` 前缀（仅当标题仍是插件维护值）；
      新目录按 A5/A6 接管或新建并绑定；不会因为旧标题未释放而多出「（2）」后缀。
- [x] **C2** 主目录从有到无（显式清空目录）→ 解绑旧工作区、去前缀、保留；空间保存成功。
- [x] **C3** 只改参考目录（第 2 个及以后）→ 工作区不动。
- [x] **C4** 主目录写法变化但 canonical 路径不变（如 `~/x` → `/home/u/x`）→ 不重建、不换绑。
- [x] **C5** 存量空间（无绑定）首次在配置页保存（或改主目录）→ 自动补绑工作区，不阻塞本次保存。

## D. 归档 / 恢复

- [x] **D1** 归档空间 → 工作区注册、标题、会话归属均不变。
- [x] **D2** 恢复空间且工作区仍在 → 不重建、不改名。
- [x] **D3** 恢复空间但工作区已被删、目录仍存在 → 重新接管/创建并绑定，标题回到 `🪐 <空间名>`。
- [x] **D4** 恢复空间但目录已不存在 → 恢复成功；工作区保持未绑定（记日志），不阻塞空间恢复。
- [x] **D5** 启动对账 → 清理孤儿绑定（空间已不存在）；**不**重建用户在 DSH 侧删除的工作区；
      空间主目录被外部清空时释放绑定。

## E. 删除空间

- [x] **E1** 删除空间 → 空间业务数据删除；工作区注册保留，标题去掉 `🪐 ` 前缀（仅当仍为插件维护值）。
- [x] **E2** 删除空间后，该工作区原有会话仍归组在该工作区（不掉入「未分组」）。
- [x] **E3** 删除空间后从 DSH 原生删除该工作区 → 正常；空间侧残留绑定由启动对账清理。
- [x] **E4** 工作区标题已被用户手工改过 → 删除空间时保持原样，不改标题。

## F. 反向与共存

- [~] **F1** DSH 原生「添加工作区」→ 空间侧不新增空间、不写入任何空间数据（实现不监听该方向）。
- [~] **F2** 侧栏工作区行的图标保持 DSH 原生文件夹图标（不做 UI 接管）；空间身份靠标题前缀识别。
- [x] **F3** 宿主没有 `workspaceRegistry` 服务 → 空间功能照常可用，但跳过工作区创建/同步（日志提示，不阻塞）。
- [x] **F4** 默认空间（`sp-inbox`，无目录、不可归档/删除）不受影响。

## H. 工作目录选择（系统选择器）

- [x] **H1** 新建空间点「选择目录」→ 直接打开宿主目录选择器（桌面为系统文件夹对话框，Web profile
      为 DSH 目录浏览），不再出现 Space 自绘的目录浏览器；与 DSH 自身「添加工作区」使用的是同一个
      `uiWorkspace.pickDirectory()`。
- [x] **H2** 选中的路径直接追加到已选目录：取消不改动；重复选择同一目录去重；可多次点击添加多个目录。
      按钮文案随状态变化：还没有目录时是「选择工作区」，已有目录后是「选择资料库」。
- [x] **H3** 空间配置页的「工作目录」走同一选择器（`ConfigView` 与 `CreateSpaceDialog` 都指向覆盖组件）。
- [x] **H4** 已选目录的 chips、名称/路径、移除按钮、错误提示与原先视觉一致；提示文案为
      「工作目录可编辑和读写，其他目录将作为资料库来源」，不再暴露「主目录 / 参考目录」的内部映射术语。
- [~] **H5** 宿主没有 `uiWorkspace.pickDirectory` 时：字段直接渲染内置目录浏览器；选择过程中才报告
      不可用时（`directory-picker-unavailable`）点击后退回内置浏览器。无 provider 的 SSR 回退已测，
      `directory-picker-unavailable` 的点击回退只做代码审查（无 DOM 测试环境）。
- [x] **H6** 构建隔离：`build/build.mjs` 只重定向两个导入点（构建产物中
      `CreateSpaceDialog`/`ConfigView` 引用覆盖组件，原组件仅作为回退被引用），`scripts/verify.mjs` 校验 bundle 标记，
      `tests/directory-field-override.test.ts` 校验重定向规则本身。
